4-Bit Quantization: Precision Dequantization Techniques for GEMMs

In this post, we'll explore how to efficiently handle quantized matrices in deep learning, focusing on a specific case: performing matrix multiplication between a float16 matrix A and a quantized int32 matrix B that packs 4-bit values.

Understanding Quantization

Before diving into dequantization, let's understand how quantization works. The process involves converting high-precision numbers (like float16) into lower-precision formats (like 4-bit integers) while preserving as much information as possible.

Group-wise Quantization

The quantization process involves calculating two key values for each group:
  • Scale = $\frac{max(original) - min(original)}{max(quantized) - min(quantized)} $
  • Zeros = $min(original)$
For example, converting $[-5.5, 4, 9, 3.4]$ to 4-bit unsigned integers (range 0-15):
scale = (9 - (-5.5)) / (15 - 0) ≈ 0.97
Zeros = -5.5
The quantization formula is:
$q = round(\frac{x - zeros}{scale})$
Applying this to our example gives us: $[0, 10, 15, 9]$

Grouping Strategy

When quantizing matrices, we don't calculate scale and zeros for the entire matrix at once. Instead, we group similar values together to minimize precision loss. Column-wise grouping typically provides the best results since features for each token are stored in columns, making their values have a similar scale. However, this is massively expensive due to the common row-wise memory layout. (See memory-coalescing). In our implementation, as we don't deal with quantization, we use column-wise partitioning, where scales and zeros have shape (1, N). If quantization is desired, one way to achieve it efficiently and without losing too much precision is by using 2D block-tiling, which involves dividing the matrix into rectangles. For more details: GridQuant

The Challenge: Packed Values

Our quantized values come packed in int32 format, with each int32 storing eight 4-bit numbers $(32//4)$. Let's understand this with a simpler example using int16 packing four 4-bit numbers: Consider the number $1001$ $1000$ $1101$ $1111$ ($39135$ in decimal). We interpret this as four separate values: $(9, 8, 13, 15)$ To extract these values, we use bit-wise operations:
  • 1. Shift the desired 4 bits to the rightmost position
  • 2. Apply a mask to clear unwanted bits
    • Example: To extract the second value ($1000$):
    n = 1001 1000 1101 1111
    shifted_n = n >> 8
    print(shifted_n ) -> 0000 0000 1001 1000
    mask = 0000 0000 0000 1111
    unpacked = mask & shifted_n = 0000 0000 0000 1000
    print(unpacked) -> 0000 0000 0000 1000

    Implementation Details

    Our implementation works with:
    • A: shape (M, K) in float16
    • B: shape (K//8, N) in int32 (packed 4-bit values)
    • C: shape (M, N) in float16
    • scales: shape (1, N) in float16
    • zeros: shape (1, N//8) in int32 (packed values)

    Differences with Standard GEMM Implementation

    Assuming familiarity with standard GEMM implementations in Triton, let's analyze the key differences in our quantized version. The first significant change is how we handle matrix B's values. Since each int32 value packs eight 4-bit elements, accessing the first eight rows of the actual matrix means accessing just the first row of matrix B. This affects how we calculate our pointers:
    b_ptrs = b_ptr + (off_k[:, None]//8)*stride_bk + off_bn[None,:]
    Before entering the main loop, we need to load scales and zeros. Remember that zeros is also quantized, requiring special handling:
    sc = tl.load(scales_ptr + tl.arange(0, Bc))
    z = tl.load(zeros_ptr + off_bn//8)
    We calculate bit shifts for both the values and zeros:
    shift = (off_k % 8)*4
    shift_zeros = (off_bn % 8)*4
    Then, we extract the actual zero values:
    z = (z >> shift_zeros)& 0xF
    z = (z + 1) * sc # (1, N), float16
    Finally, inside the main loop, we unpack and scale the values from B:
    b = (b >> shift) & 0xF
    b = b*sc + z # scale b, float16
    These modifications allow us to efficiently work with quantized values while maintaining the overall GEMM structure.
